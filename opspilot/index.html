Two Operating Modes

Reactive vs Proactive

OpsPilot works in two modes. In Reactive mode an operator asks in Teams and OpsPilot acts and replies. In Proactive mode no one asks — the agent notices a problem itself, applies a pre-approved safe fix itself, verifies the result, and reports the final outcome in Teams.

Reactive — You Ask, OpsPilot Acts

Trigger: an operator sends a message in Microsoft Teams. Nothing runs until someone asks.

💬
Operator asks in Teams
teams_bot.py · Bot Framework Webhook (HTTPS)

Examples: service status, CPU / RAM, restart service, log queries — or a runbook question.

🎯
Intent Detection & Guardrails
detect_intent() · operation_guardrails.py

OpsPilot identifies the operational intent and validates that the requested action is safe to execute.

🔀
Router → Agent Execution
operation_router.py · POST /cerebro/agent/execute

The Operation Router resolves the target server from the registry and the HTTP Agent Client sends the command to its PowerShell agent.

💬
Callback → Teams Reply
agent_response_callback · response_formatter.py

The agent returns JSON via HTTP callback, the Response Formatter formats it, and the operator gets the result in the same Teams chat.

At a glance — Reactive

  • ✓Started by: a person asking in Teams
  • ✓OpsPilot does: checks, executes the approved operation, or answers from knowledge
  • ✓Teams output: a direct reply to the request
  • ✓Logged in: TelepathicSession & OperationLog

Proactive — OpsPilot Watches, Fixes, Reports

Trigger: monitoring on the managed server — not a Teams message. No ticket and no operator prompt comes first.

👁️
Agent notices the issue itself
PowerShell Agent · cerebro_agent.ps1 / cerebro_http_agent.ps1

The on-server agent detects a condition such as a stopped or unhealthy service during its checks.

🛡️
Guardrails check the safe-fix list
operation_guardrails.py

Only a pre-approved, allowlisted remediation may run automatically. Anything outside that list is not executed.

⚡
Agent fixes it itself & verifies

The agent executes the approved fix locally on the Windows server, then re-checks the service / metric to confirm it is healthy again.

📣
Final outcome reported in Teams
agent_response_callback · response_formatter.py

OpsPilot posts the final outcome in Teams — what was detected, what was fixed, and the verified result — and writes it to OperationLog.

If it cannot fix safely: if the fix is not pre-approved, or verification fails, OpsPilot does not force an unsafe action — it alerts the team in Teams for human intervention instead.

At a glance — Proactive

  • ✓Started by: the agent detecting a problem itself
  • ✓OpsPilot does: applies a pre-approved safe fix itself, then verifies
  • ✓Teams output: a final-outcome report — or an alert if a human is needed
  • ✓Logged in: OperationLog audit trail

Infrastructure Server Registry

OpsPilot maintains a registry of managed servers mapping server names to IP addresses. Model: infrastructure/models.py

name — Friendly server name
hostname — Server hostname
ip_address — IP used for agent communication
environment — Classification (prod / test)
agent_token — Auth token for agent communication

Server Resolution Flow

User Request→Operation Router→HTTP Agent Client→Server Resolver→Server Model (DB)→Resolved IP Address

Operators say a friendly name like SRV01 — the registry resolves it, e.g. 192.168.1.10.
